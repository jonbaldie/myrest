# Verification: meta + index, rewritten scenarios, derived gap list

The parent spec must say how parity is proven without becoming a test runner or a second label matrix. **Decision** (from [Decide normative verification approach](https://github.com/jonbaldie/myrest/issues/12)): the Verification **capability area** holds method, done rules, gap-list format, scenario index, and a fixed cross-area smoke set — not full scenario bodies and not a global behaviour×label matrix. Each **capability area** chapter owns rewritten **normative scenarios** (optional PostgREST cite; fixture **intent** only). Coverage follows the **parity label**: **full match** needs success (and claimed errors only when named); **partial match** needs in-subset success plus outside-subset refuse; **not supported** needs refuse only. The **gap list** is a derived roll-up of chapter **partial match** and **not supported** rows. Scenarios are binding acceptance criteria; the parent spec does not mandate CI or test framework. Parent-spec lock requires every labelled behaviour to have its required scenario(s), with stable ids (`area-nnn`).

**Why:** Chapters already own labels; Verification must define proof and “done” without drift. Rewritten scenarios beat cite-only upstream tests for a MySQL product. A derived gap list stays honest to those labels.
