# Schema cache: config ∩ grants, explicit reload, declared FKs only

myrest must expose a PostgREST-like surface over MySQL without a second ACL and without Postgres catalog features. **Decision** (from [Decide schema cache and resource exposure model](https://github.com/jonbaldie/myrest/issues/7)): the **schema cache** holds catalog data for configured MySQL databases (tables, views, columns, keys, foreign keys, routines, grants, comments). A catalog object is a **resource** for a request only if its database is in the config schema list and the active **database role** has a relevant privilege on it; method allow-lists still follow the specific grant, and MySQL enforces grants after **role switch**. Object kinds: tables, views, routines (functions and procedures). Relationships in the cache are declared foreign keys only — view-chain embed without a declared FK is **not supported**. PostgREST-style domains, casts, and row computed-fields are **not supported**. Refresh is by **explicit reload** only (no `NOTIFY` requirement); after a successful reload the cache must match current catalog and grant data used for exposure.

**Why:** Matches PostgREST’s privilege-filtered surface and ADR 0002’s grant-based authz, stays honest about MySQL catalog limits, and avoids an SQL view analyzer or a fake domain/cast catalog in this effort.
