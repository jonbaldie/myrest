# Config delivery: PostgREST-shaped file, env wins, unknown names refused

[ADR 0007](0007-config-surface-mapping.md) fixed *which* **knobs** myrest keeps, but not how an operator gives them. **Decision** (from [Config surface and serve gate](https://github.com/jonbaldie/myrest/issues/23)): the config file is a small PostgREST-shaped subset — one `knob = value` pair per line, `#` comment lines, double-quoted text, and bare booleans and integers. The one optional process argument is the path of that file, as the parity target does it. A `MYREST_*` variable that holds a value wins over the same knob in the file, again as the parity target does it; an empty variable counts as a variable nobody set, so an empty deploy variable cannot wipe a file value. myrest refuses a config file that holds a name outside the normative surface, and refuses a value that does not match the type of the knob, instead of ignoring either one. The environment cannot get the same refusal, because the environment is shared space that holds names myrest must not judge (`MYREST_LISTEN`, and the variables of other programs); myrest reads only the `MYREST_*` names it knows. `$(VAR)` interpolation inside file values is not part of this subset. A bind address (`MYREST_LISTEN`) is process tuning, so it has no file entry.

**Why:** Operators keep their PostgREST file and their twelve-factor deploys, with one precedence rule to remember. A refusal that names the file line and the knob turns a typo, or a knob on the drop list, into an early stop instead of a silent surprise on the wire. The interpolation and in-database paths stay out, so the surface holds only what the drop list allows.
