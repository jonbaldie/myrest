# A bare table name reads the default database, and role grants reach through granted roles

`db-schemas` can list more than one MySQL database, and `GET /<table>` names no database. **Decision:** a request that names no database reads the **default database**, which is the first database of `db-schemas`; a table of the same name in another configured database is not reachable until `Accept-Profile` (reads) or `Content-Profile` (writes) names its database. A profile value outside `db-schemas` refuses with `PGRST106`. A table of the selected database is a **resource** when the active **database role** holds `SELECT` on it, of itself or through a role that MySQL granted to it; myrest reads the role grants from `information_schema.APPLICABLE_ROLES` with every role of the authenticator active (ADR 0010).

**Why:** The parity target reads the first schema of the list until a profile header names another one, and a search over every configured database would let the answer of one table name depend on the order the catalog gives back. Following the role grants keeps the **schema cache** in step with what MySQL permits: MySQL reads with the privileges of the roles granted to the active role, so a cache that reads the grant rows alone refuses a read MySQL allows. **Consequence:** an operator who exposes two databases must know that only the first one answers without a profile header, and a role granted to the anonymous role widens what an anonymous client reads.
