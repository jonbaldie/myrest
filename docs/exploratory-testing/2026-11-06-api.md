## Setup

The pass built the service with Go 1.26.8 and `go build -mod=readonly`. It used a worktree with separate module and build caches. `go mod verify` passed. Each run used a new MySQL 8.0 container from the existing image `sha256:7dcddc01f13bab2f15cde676d44d01f61fc9f99fe7785e86196dfc07d358ae2b` and loaded `testdata/fixtures/schema.sql`. The service used the fixture's authenticator and anonymous role. `db-tx-end` was `commit-allow-override` so that the transaction preference could be tested. The HTTP listener was `127.0.0.1:33176`.

The first setup failed because the container did not have the `myrest` account expected by the fixture loader. The cleanup trap removed that container. The next runs used the `MYSQL_USER` and `MYSQL_PASSWORD` settings from `internal/mysqltest/harness.go` and loaded the fixture. This was a test setup error, not a product finding.

The driver records container and process IDs before use and removes both on exit. It records volume IDs at cleanup and checks that they no longer exist. Run it from this checkout with Docker and Go available. It uses port 33176 and leaves temporary files under `.run`. The driver prints HTTP responses; it does not assert them. Compare them with the evidence files.

## Journeys and results

### Read and page related rows

The goal was to read and page fixture items and their orders, as described in [ordinary reads](../ordinary-read.md) and [embeds](../embed.md).

- `select=id,name&order=id.asc&limit=1` returned `alpha` with status 200.
- `Range: 1-1` with `Prefer: count=exact` returned `beta`, status 206, and `Content-Range: 1-1/2`. The replay also used `limit=1&offset=1` and got `beta`.
- An orders embed sorted by descending order ID returned orders 2 and 1 for item 1, and order 3 for item 2.

### Create, change, delete, and roll back an item

The goal was to write an item and read the lasting state, as described in [ordinary writes](../write.md) and [transactions](../transactions.md).

- POST created item 9001. PATCH changed its name. A GET returned the changed name. DELETE returned the row, and a later GET returned an empty array.
- POST with `tx=rollback` returned a representation of item 9002, but a later GET returned an empty array. POST with `tx=commit` created item 9003, and a later GET returned that item.
- The replay sent bulk objects with different keys. The service returned 400 `PGRST102`, and neither item existed afterward. The replay also sent `columns=id` on POST. The service returned 400 `MYREST001`, and no item was created. These results agree with the documented refusals and the fixes for [#266](https://github.com/jonbaldie/myrest/issues/266) and [#265](https://github.com/jonbaldie/myrest/issues/265).

### Call a routine and check its effects

The goal was to call a function and a modifying procedure, then check transaction effects as described in [RPC](../rpc-procedures.md) and [transactions](../transactions.md).

- POST `add_them` with 1 and 2 returned `3`. GET with 4 and 5 returned `9`. A POST with an unknown argument returned 404 `PGRST202`, as documented for routine lookup.
- POST `write_marker` with `tx=rollback` returned 200. A later GET found no marker. The same call with `tx=commit` returned 200, and a later GET found one marker.
- A GET `add_them` request with an extra unqualified parameter returned 400 `PGRST100` because that parameter was parsed as a filter. [RPC row sets](../rpc-row-set.md) treats non-parameter keys as read features, but also describes a `MYREST001` refusal for read features on scalar results. The expected result for this malformed filter remains unresolved without a target-contract check.

## Findings and limits

No new bug was confirmed. No issue was filed. [#261](https://github.com/jonbaldie/myrest/issues/261) already tracks a bounded JSON input problem. This pass did not test oversized bodies. The prior rejection of [#154](https://github.com/jonbaldie/myrest/issues/154) cites the Range fix in [#151](https://github.com/jonbaldie/myrest/pull/151); the Range request above returned the requested slice on this build.

The tracker and existing worktrees were checked before the pass. Open [#241](https://github.com/jonbaldie/myrest/issues/241) and [PR #276](https://github.com/jonbaldie/myrest/pull/276) cover error translation. No product code was changed.

The pass did not exercise JWT role selection, concurrent writes, schema reload, or an independent PostgREST oracle. A successful result here does not establish parity for those areas. The unknown GET parameter response is not a finding without a target-contract check.

The cleanup trap used `docker rm -fv` for the anonymous volumes. The earlier logs did not record volume IDs. The final driver run recorded its volume ID and verified its removal.
