## 2. Journeys Exercised

### Journey 1: Schema Discovery & Introspection

**User Goal:** Discover exposed endpoints, allowed HTTP methods, and API definitions via `GET /` and `OPTIONS`.

- **Ordinary Path:**
  - `GET /` with default headers returns OpenAPI 2.0 JSON document (`Content-Type: application/openapi+json`).
  - Tables with `myrest_anon` grants appear in `paths` (`/items`, `/profiles`, `/orders`, etc.).
  - `OPTIONS /items` returns status 200 with `Allow: OPTIONS,GET,HEAD,POST,PUT,PATCH,DELETE`.
  - `OPTIONS /orders` returns status 200 with `Allow: OPTIONS,GET,HEAD,POST,PUT` reflecting lack of `UPDATE`/`DELETE` grants.
- **Variations & Edge Cases:**
  - `GET /` with `Authorization: Bearer <token>` for `myrest_user` dynamically exposes `/secrets`.
  - `OPTIONS /secrets` without token returns 404 `PGRST205`; with valid JWT returns 200 with `Allow: OPTIONS,GET,HEAD`.
  - `OPTIONS /items_stats` (non-updatable view) omits write methods (`Allow: OPTIONS,GET,HEAD`) despite underlying `INSERT` grant.
  - `OPTIONS /rpc/write_marker` omits read methods (`Allow: OPTIONS,POST`) due to `MODIFIES SQL DATA`.
  - `OPTIONS /` without CORS headers returns 404 `MYREST003`; with CORS preflight headers (`Origin`, `Access-Control-Request-Method`) returns 200 with `Access-Control-Allow-Methods`.

### Journey 2: Complex Reads, Filtering, Pagination, and Embeds

**User Goal:** Query data with column projections, operators, complex logical trees, ordering, pagination, and relation embeds.

- **Ordinary Path:**
  - Basic read: `GET /items?select=id,name` returns JSON array.
  - Filters: `eq`, `neq`, `gt`, `gte`, `lt`, `lte`, `like`, `ilike`, `is`, `in`, `isdistinct`.
  - JSON path extraction: `GET /profiles?select=id,meta->tag,meta->>tag` and filters like `meta->>blood_type=eq.A-`.
  - Foreign key embeds:
    - Many-to-one: `/orders?select=id,items(id,name)`.
    - One-to-many: `/items?select=id,name,orders(id)`.
    - Many-to-many: `/items?select=id,name,tags(id,name)`.
- **Variations & Edge Cases:**
  - Empty in-list `name=in.()` returns empty array `[]`.
  - Ambiguous embed without hint (`/deliveries?select=id,addresses(label)`) returns 300 Multiple Choices with `PGRST201` and disambiguation hints. Disambiguated `addresses!deliveries_from` succeeds.
  - Self-referential embed without hint (`/employees?select=id,name,employees(name)`) returns 300 `PGRST201`. Disambiguated `employees!employees_manager` (many-to-one) and `employees!manager_id` (one-to-many) both succeed.
  - Singular object representation `Accept: application/vnd.pgrst.object+json`:
    - 0 rows: 406 Not Acceptable (`PGRST116`, "The result contains 0 rows").
    - 1 row: 200 OK with single JSON object.
    - 2 rows: 406 Not Acceptable (`PGRST116`, "The result contains 2 rows").
  - CSV export `Accept: text/csv`:
    - With rows: emits header line followed by CSV data.
    - Empty result with explicit select columns: emits header line only.
    - Empty result without select: emits empty body.
  - `Range: 1-0` (inverted bounds) returns 416 Requested Range Not Satisfiable (`PGRST103`).
  - `Prefer: count=planned` and `count=estimated` return 400 `MYREST001` as documented in `docs/read-parity-boundaries.md`.
  - Nested group filters: `GET /items?and=(or(id.eq.1,id.eq.2),name.eq.alpha_merged)` succeeds.

### Journey 3: Writes, Preference Headers, and Transactions

**User Goal:** Create, update, upsert, and delete data while verifying transactional consistency and preferences.

- **Ordinary Path:**
  - `POST /items` with single object and bulk array.
  - `PATCH /items?id=eq.X` with updated payload.
  - `DELETE /items?id=eq.X` removes targeted row.
  - `PUT /items?id=eq.X` upserts by primary key.
- **Variations & Edge Cases:**
  - `Prefer: return=representation` returns affected rows honestly for tables with primary keys.
  - `Prefer: return=headers-only` sets `Location` header without body.
  - `Prefer: return=minimal` returns 201/204 with empty body.
  - `Prefer: tx=rollback` with `db-tx-end = commit-allow-override` verifies mutations roll back cleanly.
  - `Prefer: max-affected=1,handling=strict` on a `PATCH` affecting 6 rows returns 400 `PGRST124` and leaves data unmodified.
  - `POST /colors` with omitted column keys:
    - Without `missing=default`: fails with 409 `MYREST002` on NOT NULL column without value.
    - With `Prefer: missing=default`: populates column default value (`plain`) and succeeds.
  - Unbounded write protection: `PATCH /items` and `DELETE /items` without filter return 400 `PGRST100`. Supplying `Prefer: all-rows` allows the operation.
  - Writing to non-updatable view `POST /items_stats` returns 400 `MYREST001` ("The view is not updatable").
  - Singular object `Accept: application/vnd.pgrst.object+json` on POST/PATCH/DELETE returns 406 and rolls back mutations if row count is not 1.

### Journey 4: RPC Routines & Authentication

**User Goal:** Invoke stored procedures and functions under anonymous and authenticated roles.

- **Ordinary Path:**
  - `GET /rpc/add_them?a=10&b=20` executes read-safe function.
  - `POST /rpc/add_them` with JSON body executes function.
  - `POST /rpc/echo_name` and `POST /rpc/bump_label` execute procedures with IN/OUT parameters.
  - `GET /rpc/list_items` and `POST /rpc/list_items` return tabular row-set results.
- **Variations & Edge Cases:**
  - `GET /rpc/write_marker` on routine with `MODIFIES SQL DATA` returns 400 `MYREST001` ("Only a read-safe routine can be called with GET").
  - Routine with missing or extra parameters returns 404 `PGRST202`.
  - Anonymous request to `/secrets` returns 404 `PGRST205`.
  - Bearer JWT with valid signature and `myrest_user` role successfully accesses `/secrets`.
  - Expired token and bad signature both return 401 Unauthorized.

## 3. Confirmed Bugs Filed

### [Issue #184](https://github.com/jonbaldie/myrest/issues/184): `order nulls options (nullsfirst/nullslast) fail with leaked ticket message and are missing from parity docs`
- **Impact:** Requests using PostgREST nulls ordering (`order=id.asc.nullsfirst`, `order=id.desc.nullslast`) fail with HTTP 400 `PGRST100` and error message `"nulls order options are not available in this ordinary-read ticket"`. The message leaks internal ticket tracking text to clients, and the behavior lacks a classified parity label in documentation and the gap list.
- **Status:** Filed as `bug, needs-triage`.

### [Issue #185](https://github.com/jonbaldie/myrest/issues/185): `Spread embed requests fail with leaked ticket message and unclassified parity label`
- **Impact:** Ordinary spread embed requests without aggregate functions (`GET /orders?select=id,...items(name)`) fail with HTTP 400 `MYREST001` and error message `"PostgREST spread embeds are not available in this aggregate ticket"`. The error message leaks internal ticket terminology and misattributes the failure to aggregates. Non-aggregate spread embeds are not documented in `docs/embed.md` or the verification gap list.
- **Status:** Filed as `bug, needs-triage`.

## 5. Usability & Environmental Observations

1. **`OPTIONS /` vs CORS Preflight:**
   Direct `OPTIONS /` without CORS preflight headers (`Origin` and `Access-Control-Request-Method`) returns 404 `MYREST003` (`The requested path and method are not available`), while `GET /` and `HEAD /` serve the OpenAPI document. Clients or health checkers probing root with `OPTIONS` will see 404 unless headers are provided.
2. **`Range: items=0-0` Header:**
   The PostgREST documentation notes `Range: items=first-last`. `myrest` parses `first-last` only; any unit prefix like `items=` causes the entire Range header to be ignored (returning full results) per `docs/ordinary-read.md`.

Over 180 HTTP requests were executed covering the public surface of `myrest`.
